# PROJECT OVERVIEW

## Project Purpose
Moda Clothing Store is a premium e-commerce web application designed to offer an immersive and intelligent shopping experience. It provides advanced features such as an AI-powered shopping assistant, an outfit builder, and a virtual try-on experience. 

## Main Business Objectives
- Provide a seamless end-to-end shopping journey from product discovery to checkout.
- Leverage AI to act as a personalized shopping assistant capable of multi-language customer support.
- Enable users to visualize fashion combinations using an Outfit Builder and AI Virtual Try-On.
- Provide a comprehensive Admin dashboard to manage products, categories, orders, coupons, and shipping.

## Target Users
- **Customers**: Shoppers looking for premium clothing, personalized fashion recommendations, and a streamlined purchasing process.
- **Administrators**: Store managers needing an intuitive interface to handle inventory, fulfill orders, and configure promotions.

## Main Features
- **User Authentication**: Secure signup/login with JWT-based session management.
- **Product Catalog**: Browsing, filtering, and rich product detail pages.
- **AI Chatbot**: Context-aware assistant that tracks orders, recommends products, and handles natural language searches in multiple languages (Turkish, Arabic, English).
- **Outfit Builder & Virtual Try-On**: Tools for creating outfits and generating AI previews of how combinations look.
- **Cart & Checkout**: Shopping cart management, address saving, and order processing.
- **Elasticsearch Engine**: High-performance, fuzzy-search capabilities for the product catalog.

# HIGH LEVEL ARCHITECTURE

## System Architecture
The application uses a standard decoupled Client-Server architecture.
- **Frontend**: A Single Page Application (SPA) built with React and Vite.
- **Backend**: A RESTful API built with FastAPI (Python).
- **Database**: A relational PostgreSQL database accessed via SQLAlchemy ORM.
- **Search Engine**: Elasticsearch for advanced and fast product queries.
- **AI Integration**: Google Gemini API for natural language processing and image generation.
- **Cloud Storage**: Cloudinary for storing product and AI-generated images.

## Architectural Pattern
- **RESTful API**: Standardized endpoints for CRUD operations.
- **Repository/Service Pattern**: Data access logic is isolated in SQLAlchemy models and router dependencies.
- **Component-Based UI**: The frontend is strictly modularized into reusable React components.

## Service Interactions
1. **Client to API**: The React frontend communicates with the FastAPI backend via HTTP/REST.
2. **API to Database**: FastAPI uses SQLAlchemy (synchronous) to query the PostgreSQL database.
3. **API to Search Engine**: FastAPI communicates with the Elasticsearch cluster to index products and resolve search queries.
4. **API to AI/External**: FastAPI makes outbound HTTP calls to Google Gemini for NLP tasks/image generation, and to Cloudinary for image hosting.

# PROJECT DIRECTORY ANALYSIS

## Backend (`/backend/app/`)
- **`main.py`**: The entry point of the FastAPI application. Handles CORS configuration, router inclusion, and startup lifecycle events (like syncing the Elasticsearch index).
- **`database.py`**: SQLAlchemy engine and session management configuration.
- **`dependencies.py`**: FastAPI dependency injection (e.g., getting DB sessions, fetching the current authenticated user).
- **`core/`**: Core utilities.
  - `config.py`: Environment variable and settings management (Pydantic Settings).
  - `search.py`: Elasticsearch integration, index creation, product indexing, and search execution.
  - `security.py`: Password hashing and JWT generation logic.
  - `cloud_storage.py`: Cloudinary upload logic.
- **`models/`**: SQLAlchemy ORM models representing database tables.
- **`schemas/`**: Pydantic models for request validation and response serialization.
- **`routers/`**: API endpoint definitions categorized by domain (e.g., `ai.py`, `auth.py`, `products.py`, `orders.py`).

## Frontend (`/frontend/src/`)
- **`main.jsx` / `App.jsx`**: React application entry point and root layout/routing provider.
- **`api/`**: Axios instances and API wrapper functions for interacting with the backend.
- **`components/`**: Reusable UI components.
  - `layout/`: structural components (Header, Footer, AdminLayout).
  - `ui/`: Generic UI elements (Toast, Tabs, ProductCard, Carousel, TryOnModal, FloatingChat).
- **`context/`**: React Context providers for global state management (`AuthContext`, `CartContext`, `AppContext`, `ThemeContext`).
- **`pages/`**: View components for different routes, split into `admin/`, `customer/`, and `auth/`.
- **`styles/`**: Global CSS, primarily configuring Tailwind CSS.
- **`utils/`**: Helper functions (e.g., `geminiService.js`, `tryOnCategories.js`).

# APPLICATION FLOW

1. **User enters the system**: The user loads the React SPA. `AuthContext` checks for an existing JWT token in local storage.
2. **Authentication process**: If logging in, the user submits credentials. The backend verifies the password via `bcrypt` and returns a JWT. The frontend stores the JWT and attaches it to subsequent API requests.
3. **Frontend request lifecycle**: User interacts with a page (e.g., viewing the catalog). A React `useEffect` triggers an API call via the functions in `frontend/src/api/`.
4. **Backend processing lifecycle**: The FastAPI router intercepts the request. Dependencies (like `get_db` and `get_current_user`) inject the DB session and authenticate the user. 
5. **Database interactions**: The router queries or mutates data via SQLAlchemy models and commits the transaction.
6. **Search operations**: When searching, the backend queries Elasticsearch (`search.py`). If ES is unavailable or yields zero results, it falls back to a PostgreSQL `ILIKE` query.
7. **AI operations**: When a user messages the AI chatbot, `routers/ai.py` extracts intent (order, coupon, product). It queries the DB/ES to fetch real context, optionally translates the query using Gemini, formats a response prompt, and streams/returns the answer.
8. **Response generation**: Pydantic schemas serialize SQLAlchemy models into JSON.
9. **Frontend rendering**: React receives the JSON, updates its local state/context, and triggers a re-render to display the data (e.g., populating `ProductCard` components).

# DATABASE ANALYSIS

## Core Models (`backend/app/models/`)

- **User**: Stores authentication and profile data. 
  - *Fields*: user_id, email, password_hash, role (admin/customer).
  - *Relationships*: 1-to-Many with Orders, Addresses, Favorites, Reviews, Conversations.
- **Product**: Main catalog entity.
  - *Fields*: product_id, name, description, price, category, status.
  - *Relationships*: 1-to-Many with ProductVariant, Review, OutfitProduct.
- **ProductVariant**: Specific variations (size, color, stock) of a product.
  - *Fields*: variant_id, product_id, size, color, stock, images.
- **Category**: Hierarchical product categories.
  - *Fields*: category_id, name, parent_id.
- **Order & OrderItem**: Purchasing records.
  - *Fields*: orderid, user_id, total_price, status (Order); variant_id, quantity, unit_price (OrderItem).
- **Shipping**: Delivery tracking information linked to an Order.
- **ShoppingCart**: Temporary holding of variants and quantities for a user.
- **Address**: User shipping locations.
- **Coupon**: Discount codes.
  - *Fields*: coupon_code, discount, min_order_amount, usage_limit, is_active.
- **Favorite**: User wishlists.
- **Conversation & Message**: Persistent chat history for the AI assistant.
- **Outfit & OutfitProduct**: User-created combinations of clothing.
- **Invoice**: Billing records.

# AI SYSTEM ANALYSIS

## Architecture
The AI system relies heavily on **Google Gemini (`gemini-2.5-flash`)**. It is designed as a Retrieval-Augmented Generation (RAG) system where the backend fetches live store data before asking the LLM to generate a response.

## Request Lifecycle (`routers/ai.py`)
1. **Intent Detection**: The backend parses the incoming chat message to classify the intent (e.g., checking an order, looking for a coupon, or searching for products).
2. **Context Retrieval**:
   - *Order/Coupon/Address Intent*: The backend executes SQL queries to fetch the user's specific data.
   - *Product Intent*: The backend uses a custom heuristic to extract color hints, translates the query into Turkish via a rapid Gemini prompt, and searches Elasticsearch (or the DB fallback).
3. **Prompt Generation**: The retrieved data (products, stock, user name, order status) is injected into a strict `SYSTEM_INSTRUCTIONS` prompt. This prevents hallucinations.
4. **LLM Generation**: Gemini generates a plain-text, UI-friendly response in the user's detected language.
5. **Virtual Try-On**: The AI router also handles generating image collages or utilizing Gemini's vision capabilities to preview outfits.

# SEARCH ENGINE ANALYSIS

## Implementation
Search is powered by an Elasticsearch (ES) 8.13.0 single-node cluster. 

## Index Structure (`core/search.py`)
- **Index Name**: `products`
- **Mappings**:
  - `product_id` (integer)
  - `name`, `description`, `category`, `colors` (text - optimized for fuzzy matching)
  - `status`, `department`, `outfit_slot` (keyword - optimized for exact filtering)
  - `price` (float)

## Search Lifecycle
1. On app startup, `main.py` recreates the ES index and bulk-indexes all active products from PostgreSQL.
2. During a search, a `multi_match` query is executed against `name^3`, `category^2`, `colors^2`, `description`, etc.
3. It uses `fuzziness: "AUTO"` to handle typos (e.g., "denm" -> "denim").
4. If ES fails or times out, the system gracefully degrades to using SQLAlchemy `ILIKE` queries.

# SECURITY ANALYSIS

## Authentication & Authorization
- **Token Handling**: Uses JSON Web Tokens (JWT) signed via `python-jose`. Tokens expire after a configured duration (default 15 mins, configurable).
- **Password Security**: Passwords are cryptographically hashed using `passlib` and `bcrypt` before storage.
- **Route Protection**: FastAPI dependencies (`get_current_user`, `require_admin`) enforce RBAC (Role-Based Access Control) on sensitive endpoints.

## Potential Risks & Recommendations
- **Risk**: JWT tokens are currently stored in `localStorage` on the frontend, which is vulnerable to XSS attacks.
- **Recommendation**: Move JWT storage to `HttpOnly` cookies to mitigate XSS risks.
- **Risk**: The Elasticsearch node is configured with `xpack.security.enabled=false`.
- **Recommendation**: Enable ES security and use authentication credentials in production.

# PERFORMANCE ANALYSIS

- **Search Bottlenecks**: Synchronous database queries during fallback search can be slow. Elasticsearch mitigates this heavily.
- **AI Bottlenecks**: Synchronous calls to the Gemini API (`gemini-2.5-flash`) can introduce latency (500ms - 2000ms). The recent optimization to bypass LLM query translation for direct ES querying significantly improves speed.
- **Database**: Using `ILIKE` on large text fields without Postgres Trigram indexes can cause slow sequential scans.
- **Recommendation**: Implement caching (e.g., Redis) for frequently accessed data like categories and active coupons. Use asynchronous SQLAlchemy (`asyncpg`) to handle higher concurrency.

# DEPLOYMENT ARCHITECTURE

## Local Development Setup
- Provided via a convenience script (`run_app.sh`).
- Elasticsearch runs inside a Docker container defined in `docker-compose.yml`.
- FastAPI backend runs locally via `venv/bin/python3 -m uvicorn`.
- Frontend runs locally via `npm run dev` (Vite dev server).

## Production Architecture (Recommended)
- **Containers**: Containerize both the FastAPI backend and Vite frontend using Docker.
- **Reverse Proxy**: Use Nginx or Traefik to route traffic, terminate SSL/TLS, and serve frontend static files from the Vite `dist/` directory.
- **Database**: Managed PostgreSQL instance (e.g., AWS RDS).
- **Search**: Managed Elasticsearch cluster or self-hosted multi-node cluster.
- **CI/CD**: GitHub Actions to automatically lint, build, and deploy Docker images on push to the `main` branch.

# CODE FLOW DIAGRAMS

## 1. Request Flow (Product Search)
[Client (React)] --(HTTP GET /api/products?search=shirt)--> [FastAPI Router]
[FastAPI Router] --(query)--> [Elasticsearch]
[Elasticsearch] --(returns IDs)--> [FastAPI Router]
[FastAPI Router] --(SELECT IN IDs)--> [PostgreSQL]
[PostgreSQL] --(Product Data)--> [FastAPI Router]
[FastAPI Router] --(JSON)--> [Client]

## 2. AI Chatbot Flow
[Client] --("Do you have red shirts?")--> [AI Router]
[AI Router] --(Extract Context)--> [Search Module]
[Search Module] --(Query ES/DB)--> [Database]
[Database] --(Red Shirt Objects)--> [AI Router]
[AI Router] --(Construct Prompt with Data)--> [Google Gemini]
[Google Gemini] --(Natural Language Response)--> [AI Router]
[AI Router] --(JSON Response + Product Context)--> [Client]

## 3. Authentication Flow
[Client] --(POST /api/auth/login [user/pass])--> [Auth Router]
[Auth Router] --(Fetch User)--> [PostgreSQL]
[Auth Router] --(Verify bcrypt hash)--> [Passlib]
[Auth Router] --(Sign JWT)--> [Python-Jose]
[Auth Router] --(Return Token)--> [Client] (Stores in LocalStorage)

# DEVELOPER ONBOARDING GUIDE

## 1. How to run the project
1. Ensure Docker, Python 3.10+, and Node.js are installed.
2. Populate the `.env` file in `/backend/` and `/frontend/` with your database URL and API keys.
3. Run the orchestration script from the project root:
   `./run_app.sh`
   This will spin up Elasticsearch via Docker, start the Uvicorn backend server, and launch the Vite frontend server.

## 2. How to configure the project
- Update backend configurations in `backend/app/core/config.py` and the corresponding `.env` file.
- Update frontend environment variables in `frontend/.env`.
- Tailwind configuration is located at `frontend/tailwind.config.js`.

## 3. How to debug the project
- **Backend**: Use `print()` statements or Python's `logging` module. FastAPI provides automatic Swagger documentation at `http://localhost:8000/docs` to test endpoints easily.
- **Frontend**: Use React Developer Tools in your browser. Network requests can be monitored in the browser's Network tab.
- **Search**: Check the Elasticsearch container logs via `docker logs elasticsearch`.

## 4. How to add new features
- **Database Model**: Add a new class in `backend/app/models/`.
- **API Endpoint**: Create a new file in `backend/app/routers/` and register it in `backend/app/main.py`.
- **Frontend UI**: Create a new React component in `frontend/src/components/` and import it into the desired page in `frontend/src/pages/`. Use the `api/` directory to write the Axios fetch call.

## 5. How to deploy changes
- Build the frontend production bundle: `cd frontend && npm run build`.
- Deploy the resulting `dist/` folder to a static host (Vercel, Netlify, Nginx).
- Deploy the backend via Docker or directly on a VPS using a process manager like Gunicorn with Uvicorn workers.

# EXECUTIVE SUMMARY

## Architecture Summary
Moda Clothing Store is a robust, well-architected e-commerce platform that successfully merges traditional web shop functionalities with cutting-edge AI integrations. The use of FastAPI and React provides a fast, modern developer experience.

## Strengths
- **Decoupled Architecture**: Clear separation of concerns between frontend, backend, and external services.
- **Advanced Features**: Implementation of Elasticsearch for fast querying and Gemini for complex natural language interactions sets this application apart.
- **Clean Code**: High usage of Pydantic for data validation and SQLAlchemy for ORM interactions prevents SQL injection and ensures data integrity.

## Weaknesses & Technical Debt
- **Security**: JWTs stored in Local Storage expose the application to XSS.
- **Elasticsearch Reliability**: A single-node Docker setup for ES without persistent volume mapping means the search index must be rebuilt on every container restart.
- **Performance**: Lack of caching mechanisms (Redis) for static data like Categories or active Coupons.

## High-Priority Improvements
1. Implement `HttpOnly` cookies for authentication.
2. Introduce a background task queue (e.g., Celery) to handle AI operations and email sending asynchronously to prevent blocking the main event loop.
3. Add a persistent Docker volume for Elasticsearch data.
4. Implement database migrations using Alembic to track schema changes safely.
